# The pickup protocol ships as a `.beads/PRIME.md` override
Date: 2026-08-02
Status: accepted

Settles `anton-z45e`. Every claim below was re-run on **both** bd 1.1.0 (anton's floor,
`~/.local/bin/bd.1.1.0.bak`) and bd 1.1.2 (installed) — results identical unless noted. The
behaviours are pinned by `src/lib/beads/prime-override.integration.test.ts`, because
[help and docs are not oracles](2026-07-28-bd-workflow-primitives.md).

## Decision

**`.beads/PRIME.md` is the delivery mechanism.** It is served, verbatim, in place of `bd prime`'s
default output — on the floor as well as on 1.1.2 — so a session that has only primed this repo
learns the pickup protocol with no anton runtime present. The AC's fallback (wire the protocol
through `bd onboard`/AGENTS.md instead) is therefore **not needed**; AGENTS.md still gets a short
pointer section, for the reason in *Why* below.

```sh
bd prime | head -1                        # → "# Beads Workflow Context — anton"
~/.local/bin/bd.1.1.0.bak prime | head -1 # → identical
```

Precedence is the **local clone**, not the resolved workspace: this worktree's `.beads/PRIME.md` was
served while the Dolt DB itself resolved to the main checkout, which had no such file. A worktree
therefore teaches the protocol its own checkout is on.

**The override replaces the output ENTIRELY — persistent memories included, in every mode.**
`bd prime --memories-only`, the compact hook mode, serves the override too and emits **zero**
memories. Only `--export` bypasses the file. So `.claude/settings.json` runs two commands per hook:

```
bd prime; bd prime --export --memories-only
```

Without that second call, adding PRIME.md would have silently deleted 438 `bd remember` insights
from every session start and every compaction — a regression invisible from the file itself.
`src/lib/beads/prime-override.test.ts` gates the pairing.

## Why

`bd prime`'s stock output teaches the opposite of the protocol: "Session management: check
`bd ready` for available work", and a Starting-work snippet of `bd ready` → `bd show` → `--claim`.
That is exactly the bare-`bd ready` pickup `anton-1k8i` forbids — it serves unapproved work, targets
another machine holds, container epics, and the children of a feature already in flight. Documenting
the protocol elsewhere while `bd prime` keeps printing the wrong thing leaves the wrong instruction
in front of every primed session, so the override has to *replace* that text, not supplement it.

`AGENTS.md` gets a pointer section **outside** the `<!-- BEGIN BEADS INTEGRATION -->` markers: that
block is regenerated by `bd init` / `bd onboard` (it carries a content hash), so an edit inside it is
a change bd will overwrite. Its `bd ready # Find available work` line is bd's generic wording, and
the new section supersedes it explicitly rather than fighting the generator.

## Rejected

- **Documentation only (`skills/bd/SKILL.md`, no override).** A skill is loaded when something
  invokes it; `bd prime` is what a cold session in another clone actually reads. The protocol has to
  be in the primed output or it isn't teachable without anton.
- **Restating memories inside PRIME.md.** They are a live, growing set (438 today); a static copy is
  stale on write.
- **Dropping memory injection and telling sessions to run `bd memories`.** An instruction an agent
  may skip is not injection — the loss would be silent, which is what makes it dangerous.
- **`bd prime && bd prime --export --memories-only`.** `;` instead, so an unreadable PRIME.md costs
  the protocol but not the memories.
